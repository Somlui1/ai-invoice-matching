# AIVA Invoice Review Portal — **invoice-webV5**

> **สถานะ:** ทำงานได้จริงในเบราว์เซอร์ (no-build ES modules) · **ข้อมูลในการแสดงเป็นข้อมูลสมมติ (mock) ทั้งหมด**
> สร้างต่อจาก `invoice-webV4` โดยรื้อหน้าจอใหม่ให้ “อ้างอิง repo” แทนการ “copy ข้อมูล”
> ทุกอย่างคือ **เดโม**:ยังไม่ต่อ OCR/DMS/AP/SSO จริง (ดูหัวข้อ “สิ่งที่ยังไม่ได้ต่อ”)

จุดต่างของ v5 จาก v4 คือ **ข้อมูลอ้างอิงไม่ถูก copy มาไว้ในโค้ด UI อีกต่อไป** — ทุกตัวเลข/ข้อความ
มาตรฐานที่แสดงใน portal มาจากไฟล์ใน repo ผ่าน `tools/sync.py` พร้อม `sha256` + path + เวลา sync
กำกับไว้บนหน้าจอด้วยเสมอ

---

## 1. เริ่มใช้งาน

```bash
cd "Web portal/invoice-webV5"

python tools/sync.py            # อ่าน repo → สร้าง src/data/*.js (อ่าน repo อย่างเดียว ไม่เขียนกลับ)
node tools/build-snapshots.mjs  # รัน engine ของ repo กับเคส 22 เคส → src/data/snapshots.js
node tools/smoke-test.mjs       # เทสต์ 29 ข้อ (hygiene / provenance / domain / ui) — ต้องผ่านก่อนใช้งาน
python tools/serve.py           # เปิด http://127.0.0.1:8765/

# เทสต์ในเบราว์เซอร์จริง (ต้องมี Microsoft Edge; ไม่มี dependency ใด ๆ)
node tools/browser-check.mjs    # เปิด browser-check report เอง
```

`sync.py` ทำงานซ้ำได้เรื่อย ๆ (idempotent) และตรวจความเก่า-ใหม่ได้ด้วย

```bash
python tools/sync.py --check    # ถ้าไฟล์ใน repo เปลี่ยนโดยยังไม่ได้ re-sync → exit 1 + บอกว่าไฟล์ไหน
```

## 2. หลักการที่ v5 ยึด (และ smoke-test เฝ้าอยู่)

| ข้อห้าม / ข้อปฏิบัติ | รายละเอียด |
| --- | --- |
| **portal ไม่คำนวณผล matching เอง** | ไม่มีไฟล์ runtime ไหน import `src/engine/rules.js` (engine มีไว้ให้ `tools/build-snapshots.mjs` รันตอน build เท่านั้น) ผลตรวจที่เห็นคือ snapshot จาก engine |
| **เงินเป็น decimal string ตลอดสาย** | `src/domain/money.js` คำนวณบน `BigInt` ห้าม `Number` · `fmtMoney` ปัด 2 ตำแหน่งเมื่อแสดง |
| **UI ห้ามตัดสินใจแทน engine** | ป้าย “พร้อม/ปิดไม่ได้” มาจาก `guards.js` ที่อ่าน snapshot + หลักฐาน ไม่ใช่การเดาของ UI |
| **ข้อมูลอ้างอิงต้องชี้กลับ repo** | ทุกหน้ามี `sourceTag` บอก path ต้นทาง · หน้าที่มาข้อมูลแสดง sha256/bytes/lines/mtime |
| **sync เป็น read-only** | `tools/sync.py` ห้ามเขียนไฟล์ใด ๆ กลับเข้า `ai-invoice-matching/` |
| **standard text ห้าม copy** | หน้าคู่มือ render จาก markdown ใน repo (`src/data/repo-docs.js`) ไม่ copy ประโยคมาตรฐานมาใส่ในโค้ด |
| **ความขัดแย้งต้องมองเห็น** | มาตรฐาน vs as-built ที่ไม่ตรงกัน แสดงเป็นตารางในหน้า “กฎ & ข้อยกเว้น” ไม่ใช่เก็บไว้ในหัวคนทำ |
| **domain ไม่แตะ DOM** | `src/domain/*` เป็น ES modules ล้วน รับ `storage` ผ่าน opts → Node import ทดสอบได้ |
| **innerHTML ที่เดียว** | create DOM ผ่าน `ui/dom.js` เท่านั้น (smoke-test ไล่ตรวจทุกไฟล์) |

## 3. โครงสร้าง

```
index.html · app.js        shell + hash router + event delegate + overlay สถานะ
src/domain/                business logic (import ได้ใน Node ไม่มี DOM)
  money schema company workflow access guards audit exceptions store ruleCatalog
  mdtext.js   parser ตาราง markdown (domain ล้วน)   reference.js  เทียบมาตรฐาน vs as-built
src/engine/rules.js        code copy จาก repo (ใช้ตอน build snapshot เท่านั้น ห้าม import ตอน runtime)
src/ui/                    dom.js (create/escape/mount/toast/modal) · format.js · markdown.js · parts.js
src/views/                 work · detail · rules · manual · sources · audit  (return HTML string)
src/data/                  ← all generated by tools/sync.py · snapshots.js by tools/build-snapshots.mjs
  master-data.js  นิติบุคคล + exception codes + USER_TASK_CODES + tolerance  ← master_data.py
  repo-docs.js    markdown 5 ไฟล์ของ repo (คู่มือ render จากที่นี่)             ← docs/*.md
  design-tokens.js :root 22 ตัวแปร                                           ← mockup v4.4
  sources.js      registry แหล่งข้อมูล + sha256 + คำสั่ง sync                  ← ทุกไฟล์ข้างบน
  snapshots.js    ผลตรวจ 24 revisions ของ 22 เอกสาร                          ← engine + tools/cases-*.mjs
src/styles/app.css         tokenชุดเดียวตาม mockup + utility เล็กน้อย
tools/                     sync.py · build-snapshots.mjs · smoke-test.mjs · browser-check.mjs · serve.py
docs/                      PORTAL-plan.md · as-built-v5.md
```

**หน้าใน portal มี 6 หน้า** (`#/` `#/doc/:id` `#/rules` `#/manual` `#/sources` `#/audit`) — v4 มี 7 หน้า
(merged `master` + `rules` + `help` + `handoff` ให้ลดหลั่นกันไปอยู่ในหน้าเดียวกัน)

## 4. copy-manifest (v4 → v5)

ตรวจด้วย md5 เมื่อวันที่ทำงานเวอร์ชันนี้ (ไม่ใช่ copy แล้วลืมบอก)

| สถานะ | ไฟล์ | หมายเหตุ |
| --- | --- | --- |
| เหมือนเดิม | `src/domain/{access,audit,exceptions,guards,money,ruleCatalog,schema,workflow}.js` · `src/ui/{dom,format}.js` · `src/engine/rules.js` · `tools/cases*.mjs` | logic ผ่านเทสต์ใน v4 แล้ว ไม่แก้ |
| แก้ | `src/domain/store.js` | เปลี่ยน `STORAGE_KEY` เป็น `aiva.webv5.state.v1` (กัน overlay ชนกับ v4) ที่เหลือนอกนั้นเท่าเดิม |
| แก้ | `src/domain/company.js` | `companyOptions()` รับ `company_label` ตามโครงข้อมูลที่ store สร้างจริง |
| แก้ | `app.js` `index.html` `src/styles/app.css` `src/views/{detail,audit}.js` | router/หน้าตาใหม่ · detail ย้ายปุ่มไปอยู่กับกลุ่มงาน · audit ตัดคอลัมน์เหลือ 5 |
| ใหม่ | `tools/sync.py` | ตัว sync repo → `src/data/*.js` + registry (แทน `build-master-data.py`) |
| ใหม่ | `tools/build-snapshots.mjs` | เปลี่ยนชื่อจาก `build-fixtures.mjs` + ปรับ banner ให้บอก provenance |
| ใหม่ | `src/domain/{mdtext,reference}.js` · `src/ui/markdown.js` · `src/views/{work,rules,manual,sources}.js` · `src/data/{repo-docs,design-tokens,sources}.js` | ชั้น “อ้างอิง repo” ทั้งหมด |
| ไม่มีใน v5 | `src/views/{dashboard,queue,master,help}.js` · `tools/build-master-data.py` · `docs/0*.md` | รวมหน้าแล้ว / แทนที่ด้วย `sync.py` / เอกสารอธิบายแผนย้ายไปที่ `docs/` ของโฟลเดอร์นี้ |

## 5. สิ่งที่ยังไม่ได้ต่อ (แสดงบนหน้า Portal ให้เห็นด้วย ไม่ใช่ซ่อน)

| ประเด็น | วันนี้ | ก่อนต่อจริงต้องทำอะไร |
| --- | --- | --- |
| **Posting Gateway (ตั้งหนี้ที่ AP/Oracle)** | ปุ่ม “ส่งตั้งหนี้ที่ AP” ปิดทุกบทบาท — guard กันไว้ด้วยข้อความ “ยังไม่มีการเชื่อมต่อ Posting Gateway v1” | ทำสัญญา API + payload กับทีม AP แล้วเปิดเฉพาะบทบาท APR (state machine เผื่อ action `post` ไว้แล้ว) |
| **ส่ง OCR กลับ / Resubmit** | `outbox` เป็นรายการจำลองใน browser storage | ต่อ worker ที่ POST `/documents/{id}/revisions` จริง + ระบบ retry |
| **ต้นทาง PDF** | `pdf_synth=true` ทุกฉบับ — portal ทำ PDF เองจาก snapshot | ต่อลิงก์ DMS ตัวจริง + viewer ที่ไม่เปิดให้ดาวน์โหลด |
| **พิสูจน์ตัวตน** | เลือกบทบาทได้จาก dropdown ใน header | ต่อ SSO แล้ว map `role` + `companies` จาก token |
| **ผลตรวจจริงจาก engine** | portal ใช้ snapshot ที่ `build-snapshots.mjs` สร้างตอน build | ต่อ endpoint `POST /documents/{id}/revisions` เข้า store (`ingest` + `seenEvents` กัน `event_id` ซ้ำไว้แล้ว) |
| **master ใหญ่ 10,000 บรรทัด** | นิติบุคคล 48 แถวจาก `master_data.py` | เปลี่ยน `sync.py` ให้ pull จาก API/DB พร้อม version + TTL |

รายละเอียดเชิงเทคนิคอ่านใน `docs/as-built-v5.md` และแผนการย้ายใน `docs/PORTAL-plan.md`
